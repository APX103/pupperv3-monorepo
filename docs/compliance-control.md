# 控制硬件与柔性阻抗方案

## 芯片分工

| 芯片 | 用途 | 说明 |
|------|------|------|
| Raspberry Pi ARM64 CPU | 行走控制 + ROS2 通信 | RTNeural 实时 50Hz 推理，xsimd/NEON SIMD 加速 |
| HAILO-8 NPU | 视觉推理 | YOLOv8 目标检测、深度估计，功耗 ~2.5W |
| GPU (训练时) | RL 训练 | MJX/JAX 批量并行几千个 MuJoCo 环境 |

NEON 是 ARM 处理器内置的 SIMD 指令集（类似 x86 的 SSE/AVX），一次对多个数据做并行乘加，加速矩阵运算。不是显卡。

## MLP 推理速度

| 环境 | 单次推理耗时 | 最大频率 | 50Hz 余量 |
|------|------------|---------|-----------|
| x86 CPU (numpy) | ~291 us | 3,438 Hz | 68.8x |
| 估算 RPi ARM (无 SIMD) | ~1,164 us | 859 Hz | 17.2x |
| 控制循环目标 | 20,000 us | 50 Hz | 1x |

MLP 仅 ~196 万参数、5 层，计算量很小。RTNeural 使用 NEON 向量化后实际性能比纯 numpy 更好。HAILO 不参与行走控制，留给视觉模型更合理。

## 控制循环频率

当前：50Hz 推理，MuJoCo 仿真步长 0.004s（250Hz），每 5 步执行一次 policy。

### 提频的正面影响

- 更快修正外部扰动，抗冲击能力更强
- 更低延迟响应传感器输入

### 提频的负面影响

- 执行器/舵机总线带宽有物理限制，跟不上高频指令会引入振荡
- CPU 负载上升，RPi 功耗/发热增加
- **训练和部署必须用同一频率**，否则观测分布偏移导致 policy 退化
- 控制循环抖动风险增大，错过 deadline 更致命

### 何时需要提频

- 高速运动（奔跑 > 1m/s）
- 精细操作（后空翻、跳跃）
- 高扰动环境

提频代价不大（余量 17x），但需要重新训练。

## 柔性阻抗控制

### 当前状态：无柔性能力

现有架构为纯位置 PD 控制：
- 所有关节 `action_types: "position"`，无力矩模式
- PD 控制器刚性（kp=7.5, kd=0.25），外部力只遇到比例抵抗
- 无力反馈、无导纳回路、无扰动估计
- E-stop 时设置 kd=0.1 做软阻尼 limp 模式（最小的被动柔性）
- Policy 通过 IMU 可学会恢复（训练中的扰动），但底层控制器不会"让步"

### 已知柔性方案

#### 1. 降低 PD 增益（最简单）

被踢时动态降低 kp，机器人变软，力自然卸掉。

- **优点：** 零成本，立刻可用
- **缺点：** 太软站不稳，走路晃

#### 2. 阻抗控制 (Impedance Control)

控制关节的弹簧-阻尼特性而非位置：

```
τ = M_d * (ẍ_d - ẍ) + D_d * (ẋ_d - ẋ) + K_d * (x_d - x) + F_ext
```

- `K_d`（刚度）— 被踢时降低让关节让步
- `D_d`（阻尼）— 吸收冲击能量
- `M_d`（虚拟惯量）— 控制响应速度
- `F_ext` — 需要力/力矩传感器（当前硬件没有）

- **优点：** 自然"推让回弹"感觉
- **缺点：** 需要力矩传感器或准确估计

#### 3. 串联弹性驱动器 (SEA)

关节串联弹性体 + 编码器，通过形变测力矩。MIT Cheetah 方案。

- **优点：** 精确力控
- **缺点：** 需改硬件，成本高

#### 4. 无传感器方案（最实际）

用已有信息估算外力，不需要额外硬件：

- **动量观测器：** 用 `q, qdot, IMU` 反推外部力矩 `τ_ext = I*q̈ + C*qdot + G - τ_joint`
- **电流反馈：** 舵机驱动电流 ∝ 力矩，直接读总线电流
- **策略切换：** 检测到扰动时从行走 policy 切到低增益 limp 模式，扰动消失后切回

#### 5. 训练层面（最前沿）

- **域随机化力矩扰动：** 训练时随机施加外力，policy 学会柔性恢复
- **可变阻抗输出：** policy 不仅输出位置，还输出 kp/kd，学会何时软何时硬
- **奖励塑形：** 被踢后恢复站立 + 平滑恢复轨迹的正奖励

### 推荐方案（不改硬件）

**方案 4 + 5 组合**性价比最高：

1. 加动量观测器估算外部扰动
2. 检测到扰动 > 阈值时动态降低 kp（如 7.5 → 2.0）
3. 重新训练 policy，加入随机推力和可变阻抗输出

流程：小孩踹一脚 → 观测器检测到 → kp 降低 → 关节让步 → policy 恢复姿态 → 扰动消失 → kp 恢复。
